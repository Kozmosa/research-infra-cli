项目概览

核心问题

Agent 即兴探索

LLM Agent 自行创建目录、推断文件位置、执行 shell 命令探测环境，导致不可复现、高摩擦、协作困难。

解决方案

确定性契约

将实验完整生命周期纳入确定性的文件系统契约，所有 ground truth 通过 CLI 命令获取。

目标用户

AI Agent + 人类

Agent 通过 --json 消费结构化数据，人类通过文本输出理解状态，两者共享同一事实来源。

arcli 工作流

01 初始化仓库

生成标准研究仓库目录树，自动检测技术栈。

arcli project init ./my-project --name "My Project" --research-type ml --zh
02 注册数据

将数据集注册为资产，计算 SHA256 校验和。

arcli data register ./data/raw --name my-dataset --desc "Dataset description"
03 创建实验

声明数据、命令、环境，生成唯一实验 ID。

arcli exp new --data my-dataset --cmd "python train.py --epochs 10" --label baseline
04 执行实验

运行命令，自动捕获 stdout/stderr 到日志。

arcli exp run run-001-20260501-1200_baseline
05 记录指标

按 step 记录结构化指标，支持覆盖更新。

arcli exp metric run-001-20260501-1200_baseline --step 1 --json '{"loss":0.5,"acc":0.92}'
06 同步归档

导出 SQLite 到 JSON，纳入版本控制。

arcli db sync --mode export
git add experiments/*/experiment.json

实验状态机

实验在其生命周期中经历以下状态。

created
→
running
→
finished
running → exit(≠0) → failed
running → SIGTERM → interrupted → resume → running

双轨持久化

SQLite

.research/research.db

运行时缓存。支持高效查询、原子操作、并发写入。

JSON

experiments/*/experiment.json

版本控制事实来源。人类和 Agent 最终只需信任 JSON。

同步流程

┌─────────────┐     export      ┌─────────────────┐
│  SQLite     │ ───────────────→│ experiment.json │
│ research.db │                 │ (版本控制事实源) │
│  (运行时缓存) │ ←───────────────│                 │
└─────────────┘     import      └─────────────────┘
        ↑                              ↑
        │    db sync --mode auto       │
        │    按 updated_at 比较合并     │
        └──────────────────────────────┘

使用场景

  • 实验后: db sync --mode export 将 SQLite 写入 JSON
  • 拉取后: db sync --mode import 将 JSON 读入 SQLite
  • pre-commit: db sync --mode auto 自动比较合并

arcli 的核心设计原则

  1. 实验的单一事实来源 — 任何需要"运行实验并记录"的场景都通过 arcli
  2. Agent 原生 — 所有命令支持 --json，输出机器可解析
  3. 无状态 CLI — arcli 不维护常驻进程，状态存储在仓库文件中
  4. 双轨持久化 — SQLite 为运行时缓存，JSON 为版本控制事实来源
  5. 严格契约 — 实验创建时声明数据、命令、环境，绑定 git commit
