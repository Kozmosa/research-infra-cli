# arcli v0.2.0 Design Spec

> 基于 v0.1.0 两大测试（基础功能 + MCM2026 实战）驱动设计。
> 涵盖 v0.1.1 基础设施修补 + v0.2.0 中期能力增强。

---

## 1. 目标

### 1.1 v0.1.1 修补（附带）

| ID | 问题 | 解决方案 |
|----|------|---------|
| F01 | `exp run` 无超时控制 | `--timeout` 参数 |
| F02 | `--json` 必须写在子命令之前 | 子命令声明 `--json`（`global = true`） |
| F03 | hooks 目录为空导致首次 `exp new` 失败 | `project init` 生成 `hooks/README.md` |

### 1.2 v0.2.0 增强（主）

| ID | 问题 | 解决方案 |
|----|------|---------|
| F04 | 实验脚本不知产出写到哪里 | 环境变量注入（`$ARCLI_EXP_DIR` 等） |
| F05 | 实验产出散落各处 | `exp run` 后自动索引 artifacts |
| F06 | 历史实验无法纳入管理 | `exp import` 命令 |
| F07 | 实验间参数差异无记录 | `diff_at_creation` + `exp diff` 命令 |
| F08 | 数据资产过期无感知 | `data verify` 命令 + `data info` 检查 |

### 1.3 非目标

- 不引入 tokio 或异步运行时（保持同步、单进程）
- 不实现实验依赖图、grid search、MCP Server（延期至 v0.3.0）
- 不进行 CLI 智能推断（import 等命令保持机械性，推理由 Agent 层负责）
- 不修改现有 `experiment.json` 的必填字段结构（新增均为可选）

## 2. 实验目录协议 v2

### 2.1 核心设计

协议 v2 在 v0.1.0 结构上扩展，保持完全向后兼容。

```
experiments/{exp_id}/
├── experiment.json          # 元数据（已有，扩展可选字段）
├── logs/
│   └── run.log              # stdout/stderr（已有）
└── artifacts/               # 结构化产出（已有，增强自动索引）
    └── {脚本自行写入的文件}
```

### 2.2 `experiment.json` 新增字段（全部可选）

```jsonc
{
  // === 已有字段（不变）===
  "id": "run-001-2026-05-01-1304_baseline-smoke",
  "short_id": "001",
  "status": "finished",
  // ...
  
  // === 新增字段 ===
  "env_snapshot": {
    "ARCLI_EXP_DIR": "/repo/experiments/run-001-...",
    "ARCLI_EXP_ID": "run-001-...",
    "ARCLI_REPO_ROOT": "/repo",
    "ARCLI_LOG_DIR": "/repo/experiments/run-001-.../logs"
  },
  "diff_at_creation": "M\tsrc/params.py\n",
  "artifacts_index": [
    {"path": "artifacts/results.csv", "size": 1234},
    {"path": "artifacts/figs/loss.png", "size": 5678}
  ]
}
```

- `env_snapshot`: `exp run` 时注入的环境变量快照（用于调试和复现）
- `diff_at_creation`: `exp new` 时 `git diff --name-status`（仅记录文件名+状态，不记录完整内容）
- `artifacts_index`: `exp run` 结束后自动扫描生成（仅 path + size，不含 checksum）

### 2.3 通用性原则

- 语言无关：环境变量机制对所有语言统一
- 不强制目录深度：`artifacts/` 下的子目录结构由脚本自行决定
- 不干涉脚本逻辑：协议只规定"写到哪里可以被索引"，不规定"怎么写"
- 可选择性：脚本可以不读取环境变量，产出仍然在实验目录内

## 3. CLI 实现规格

### 3.1 `exp run --timeout`

**CLI 参数**:
```rust
// ExpCommands::Run
Run {
    exp_id: String,
    
    #[arg(long, help = "超时时间（秒），超时后发送 SIGTERM 并标记 interrupted")]
    timeout: Option<u64>,
    
    args: Vec<String>,
}
```

**实现**:
- 使用 `std::thread::spawn` + `std::sync::mpsc::channel` + `recv_timeout`
- 超时后调用 `child.kill()`（Unix 发送 SIGKILL，Windows 调用 `TerminateProcess`）
- 状态更新为 `interrupted`（复用现有 `interrupted` 状态转换）
- 不引入 tokio 或其他异步运行时

**错误处理**:
- 超时必然报错：`ArcliError::Other("实验超时: {n}秒")`
- wait 线程 panic 或 channel 断开时明确报错

### 3.2 `--json` 别名

**方案**: 从顶层 `Cli` 移除 `--json`，改用 clap 的 `global = true` 在每个子命令中声明。

```rust
// cli.rs — 顶层不再声明 --json
#[derive(Parser)]
pub struct Cli {
    #[arg(long, env = "RESEARCH_REPO")]
    pub repo: Option<String>,
    
    #[command(subcommand)]
    pub command: Commands,
}

// 在需要 JSON 输出的子命令中添加
#[derive(Subcommand)]
pub enum EnvCommands {
    Status {
        #[arg(long, global = true, help = "以 JSON 格式输出")]
        json: bool,
    },
}

#[derive(Subcommand)]
pub enum DataCommands {
    List {
        #[arg(long, global = true, help = "以 JSON 格式输出")]
        json: bool,
        #[arg(long, help = "仅显示变更的资产")]
        changed_only: bool,
    },
}

// main.rs — handler 接收 json_mode 从子命令参数中提取
fn handle_env(cmd: &EnvCommands, repo_override: Option<&str>) -> Result<(), ArcliError> {
    let json_mode = matches!(cmd, EnvCommands::Status { json: true, .. } | ...);
    // ...
}
```

**注意**: `global = true` 使参数在任何位置都可解析（`arcli --json exp list` 和 `arcli exp list --json` 都生效）。

### 3.3 `project init` 默认 hook

在 `src/commands/project.rs` 的 `init()` 中，hooks 目录创建后写入：

```rust
fs::write(research_dir.join("hooks").join("README.md"),
    include_str!("../templates/hooks/README.md"))?;
```

**模板内容** (`src/templates/hooks/README.md`):
```markdown
# .research/hooks/ 目录

## 用途

arcli 在严格模式下（`arcli env check --strict`）检查此目录是否非空。
此机制用于确保团队在运行实验前已完成必要的前置步骤。

## 使用方式

在此目录放置任意文件即可通过检查。

推荐放置内容：
- `pre-run-checklist.md` — 实验前检查清单
- 任意标记文件（空文件即可）
- 自定义验证脚本

## 注意

此目录中的文件会被纳入 Git 版本管理。
不要在此目录存放敏感信息或大型二进制文件。
```

### 3.4 `exp run` 环境注入 + artifact 自动发现

#### 3.4.1 环境变量注入

`exp run` spawn 子进程前，注入以下环境变量：

| 变量名 | 值 | 类型 |
|--------|-----|------|
| `ARCLI_EXP_DIR` | 实验目录绝对路径 | `PathBuf` |
| `ARCLI_EXP_ID` | 实验 ID（如 `run-001-2026-05-01-1304_baseline`） | `String` |
| `ARCLI_REPO_ROOT` | 仓库根目录绝对路径 | `PathBuf` |
| `ARCLI_LOG_DIR` | 日志目录绝对路径（=`ARCLI_EXP_DIR/logs`） | `PathBuf` |

实现：`Command::env(key, value)` 逐项设置。

#### 3.4.2 artifact 自动发现

子进程结束后（无论成功或失败）执行 `discover_artifacts(exp_dir)`：

**扫描范围**: `experiments/{exp_id}/`（递归遍历）

**排除规则**:
1. `experiment.json`（元数据文件自身）
2. `logs/` 目录内所有文件（已由日志系统管理）
3. 文件名以 `.` 开头的隐藏文件
4. 被 `.gitignore` 规则覆盖的文件（调用 `git2::Repository::status_should_ignore` 检查）

**输出结构**:
```rust
struct ArtifactEntry {
    path: String,   // 相对于实验目录的路径
    size: u64,      // 文件大小（字节）
}
```

**实现函数签名**:
```rust
fn discover_artifacts(exp_dir: &Path, repo_root: &Path) -> Result<Vec<ArtifactEntry>>
```

写入 `experiment.json` 的 `artifacts_index` 字段，通过 `update_exp_json` 函数追加。

**注意事项**:
- 大文件（>100MB）不跳过，继续索引（Agent 可以自主决定是否处理大文件）
- artifact 扫描失败不阻断实验状态更新（记录到 stderr 但不影响状态设为 finished/failed）

### 3.5 `exp import`

**CLI 参数**:
```rust
Import {
    #[arg(help = "要导入的目录路径")]
    path: String,

    #[arg(long, help = "实验标签（必需）")]
    label: String,

    #[arg(long, help = "原始实验命令（必需）")]
    cmd: String,

    #[arg(long, help = "关联的数据资产名称")]
    data: Option<String>,

    #[arg(long, help = "移动目录而非复制")]
    move_dir: bool,

    #[arg(long, help = "跳过确认提示")]
    yes: bool,
}
```

**导入流程**:
```
1. 验证 path 是有效目录（不是已管理的 experiment 目录）
2. 分配新 short_id（DB atomic）
3. 生成实验 ID: run-{short_id:03}-{NOW}_{label}
4. 创建 experiments/{exp_id}/ 目录
5. 复制（或移动，如果 --move）原目录内容到实验目录
6. 生成 experiment.json:
   - status: "finished"
   - command: --cmd 值
   - notes: "Imported from {original_path}"
   - commit_hash: 当前 HEAD（或无）
   - diff_at_creation: null
   - env_snapshot: null
   - artifacts_index: []  （不自动扫描）
7. 写入 SQLite + experiment.json
```

**不处理的情况**（由 Agent 负责）:
- 目录内有多个实验的混合产出
- 目录已包含 experiment.json（报错拒绝）
- artifacts_index 不为空（Agent 可通过后续工具填充）
- 目录为空（允许但不生成 artifact 索引）

### 3.6 `exp diff`

**CLI 参数**:
```rust
Diff {
    #[arg(help = "实验 ID 1")]
    exp_id_1: String,
    
    #[arg(help = "实验 ID 2")]
    exp_id_2: String,
    
    #[arg(long, help = "显示完整 diff 内容")]
    full: bool,
}
```

**输出内容**（文本模式）:
```
实验 run-001 (baseline-smoke)
  commit: a1b2c3d
  diff_at_creation: (无)

实验 run-002 (high-rocket-capacity)
  commit: e4f5g6h
  diff_at_creation: M src/params.py

git diff a1b2c3d..e4f5g6h:
----------------------------------------
 src/params.py | 2 +-
 1 file changed, 1 insertion(+), 1 deletion(-)

diff --git a/src/params.py b/src/params.py
...
```

**实现**:
- 读取两个 `experiment.json` 获取 `commit_hash` 和 `diff_at_creation`
- 执行 `git diff commit1..commit2`（如果两个 commit 都存在且可达）
- `--full` 时显示完整 diff 内容，否则只显示 stat

**错误处理**（明确报错）:
| 条件 | 错误信息 |
|------|---------|
| 实验不存在 | `实验 '{id}' 未找到` |
| 实验无 commit_hash | `实验 '{id}' 未记录 commit hash（非 Git 仓库）` |
| commit 不可达 | `commit '{hash}' 在当前仓库中不可达（可能已被 GC）` |
| commit1 == commit2 | `两个实验的 commit 相同 ('{hash}')` |
| git 命令失败 | `git diff 失败: {error}` |

### 3.7 `data verify`

**CLI 参数**:
```rust
Verify {
    #[arg(long, help = "仅显示变更的资产")]
    changed_only: bool,
}
```

**实现**:
- 读取 `data_index.yaml` 中的所有注册数据资产
- 对每个资产计算当前 SHA256 校验和，与注册值对比
- 输出每个资产的状态（OK / CHANGED / MISSING）

**文本输出**:
```
名称              路径          状态     注册时间
mnist             data/raw      CHANGED   2026-05-01 04:29
beta-coefficients data/raw      OK        2026-05-01 04:30
problem-statement data/raw      OK        2026-05-01 04:31
```

**JSON 输出**:
```json
[
  {"name": "mnist", "path": "data/raw", "status": "changed", "registered_at": "..."},
  {"name": "beta-coefficients", "path": "data/raw", "status": "ok", "registered_at": "..."}
]
```

**性能考虑**:
- 对大型文件计算 SHA256 有开销，但这是按需执行的（不自动触发）
- `data list` 不计算 checksum（只显示注册元数据）
- `data info <NAME>` 计算单个资产的 checksum 并显示状态

### 3.8 `data info` 增强

现有 `data info <NAME>` 增加状态显示：

```bash
$ arcli data info mnist
名称: mnist
路径: data/raw
状态: CHANGED (已注册校验和: sha256:abc... → 当前: sha256:def...)
描述: MNIST dataset
注册时间: 2026-05-01 04:29
```

计算单个文件的 SHA256，状态与 `verify` 一致。

## 5. 验证计划

### 5.1 单元测试

| 测试 | 验证内容 |
|------|---------|
| `test_run_timeout_kills_process` | `exp run --timeout 1 --cmd "sleep 10"` 验证超时后状态为 `interrupted` |
| `test_run_timeout_clean_exit` | `exp run --timeout 10 --cmd "echo done"` 验证正常完成不超时 |
| `test_run_injects_env_vars` | 验证子进程可读取 `$ARCLI_EXP_DIR` 等环境变量 |

| `test_discover_artifacts_respects_gitignore` | artifact 扫描排除 `.gitignore` 中的 pattern |
| `test_discover_artifacts_large_file` | 大文件正常索引（不崩溃） |
| `test_import_creates_experiment` | `exp import` 生成正确的 `experiment.json` 和目录结构 |
| `test_import_rejects_existing_experiment` | 导入已管理的实验报错 |
| `test_diff_shows_commit_diff` | `exp diff` 正确显示两个 commit 之间的差异 |

| `test_data_verify_detects_changes` | `data verify` 检测到修改的数据 |
| `test_data_list_no_checksum_overhead` | `data list` 不计算校验和 |

### 5.2 集成测试

| 测试 | 验证内容 |
|------|---------|
| 完整 MCM2026 工作流 | 从 project init → data register → exp new → exp run → exp diff → data verify → db sync 的完整链路 |
| `--json` 位置兼容性 | 验证 `arcli --json exp list` 和 `arcli exp list --json` 都输出正确 JSON |
| 向后兼容 | v0.1.0 生成的实验目录在 v0.2.0 下可正常 `exp status`/`log show`/`db sync` |

### 5.3 手动验证

```bash

# 预期: experiment.json 包含 artifacts_index

# 3. exp import

# 4. exp diff

# 预期: 显示两个实验的 commit diff

# 5. data verify
arcli data verify
# 预期: 显示所有数据资产的状态
```

## 6. 向后兼容性

- v0.1.0 的 `experiment.json` 不含新增字段（`env_snapshot`/`diff_at_creation`/`artifacts_index`），v0.2.0 读取时这些字段为 `None`
- 现有 `project init` 行为不变（默认 hook 文件不会改变目录结构）
- 现有 `exp run` 不带 `--timeout` 时行为不变
- 现有 `data list` 输出格式不变（不增加状态列）
- 不修改数据库 schema（新增字段写入 `experiment.json`，不影响 SQLite）
